F Framework Mapping Overlay — Dr. Lan's 7-Layer Semantic Filter Framework
1. Data Representation Layer 7/7 usable papers
bargain: Each record x_i in dataset D has an oracle output O(x_i), a proxy output P(x_i), and a proxy score S(x_i) ∈ [0,1] representing the proxy's confidence. For binary classification (PT/RT), proxy scores represent confidence in the positive class. For multi-class (AT), proxy scores represent confidence in the predicted class. Records are ordered/grouped by proxy scores for threshold-based decisions.
thriftllm: Queries are represented as text with prompts. For success probability estimation, queries are converted to embeddings via OpenAI's embedding API and clustered using DBSCAN. Historical performance is stored in a boolean matrix T ∈ {0,1}^{N×L} recording correctness of each LLM on each query.
nirvana: Nirvana supports tables with both structured fields (numerical, dates) and unstructured fields (text, documents, images, audio). Unstructured fields are stored as file paths pointing to remote locations (URLs, S3). Semantic operators process these multi-modal fields via LLM inference. The data model is a generalization of relational tables to accommodate heterogeneous content.
lotus: LOTUS extends the relational model with tables containing both structured data columns and unstructured free-form natural-language text columns. Semantic similarity indices (embeddings via FAISS) can be created over text columns to enable efficient semantic query processing. The data model uses a Pandas DataFrame representation.
csv: Tuples are embedded using E5-Large pretrained encoder into vector representations. For long texts exceeding context length, text is segmented into chunks and the final embedding is the mean of segment embeddings. Optionally, BM25 scores are combined with Euclidean distance via parameter α for lexically-anchored predicates. Embeddings are generated offline and are query-agnostic.
task_cascades: Documents are segmented into fixed-granularity chunks, each scored by a lightweight logistic regression classifier trained on oracle-labeled relevance data using text-embedding-3-small embeddings. Chunks are reordered so the most relevant content appears first, enabling efficient prefix-based fractional processing at fractions f ∈ {0.1, 0.25, 0.5, 1.0}.
scaledoc: ScaleDoc uses NvEmbed (derived from Mistral-7B) to generate dense semantic embeddings for each document in a one-time offline phase. These embeddings capture rich contextual semantics and are stored for reuse across all ad-hoc queries, eliminating redundant per-query document processing.
2. Candidate Executor / Proxy Layer 7/7 usable papers
bargain: The system uses a model cascade with an expensive oracle model (e.g., GPT-4o, Claude Sonnet) and a cheap proxy model (e.g., GPT-4o-mini, Claude Haiku). The proxy cost is assumed negligible relative to the oracle (>10× cost difference). The proxy provides both outputs and confidence scores (e.g., logprobabilities). Extensions to multiple proxies are discussed in Section D.
thriftllm: 12 commercial LLM APIs from 5 companies (OpenAI, Google, Microsoft, Meta, Mistral AI) serve as candidate executors with varying costs ($0.055 to $15.0 per million tokens). No traditional proxy models; instead, the method selects a subset (ensemble) of these LLMs. The surrogate function γ(S) acts as a proxy for the intractable prediction accuracy ξ(S).
nirvana: The system uses a pool of models ordered by capability and cost: gpt-4.1-nano (cheapest/weakest), gpt-4o-mini, gpt-4.1-mini, gpt-4.1 (most expensive/strongest). The physical optimizer selects per-operator backends. Additionally, the logical optimizer can replace LLM operators entirely with non-LLM compute functions (UDFs), bypassing LLM inference altogether.
lotus: LOTUS supports configuring multiple LMs (e.g., TinyLlama/Llama-8B as proxy, Llama-70B/GPT-4o as oracle) for model cascades. Embedding models (e.g., E5Model, ColBERT) serve as lightweight retrieval proxies for similarity-based operations. Cross-encoder re-rankers (e.g., MixedBread) provide intermediate-cost executors.
csv: Unlike Lotus and BARGAIN which use a smaller proxy LLM (e.g., LLaMA-3.2-3B) for initial filtering, CSV replaces per-tuple proxy LLM calling with embedding-based grouping. The embedding model serves as the cheap proxy, and only a single LLM (e.g., LLaMA-3.1-8B) is used for sampled tuples. This avoids the linear proxy scan bottleneck entirely.
task_cascades: The framework uses a cheap proxy model (GPT-4o-mini, ~17× cheaper) and an expensive oracle (GPT-4o). Both models are used to execute candidate tasks at various document fractions. The framework generalizes to any number of models but experiments focus on the two-model setting. An LLM agent (o1-mini) is used separately for surrogate operation generation.
scaledoc: The proxy is a query-specific 3-layer MLP trained online via contrastive learning on pre-computed embeddings. It produces cosine similarity decision scores. The oracle is GPT-4o accessed via API. The proxy is extremely lightweight compared to LLM cascade proxies (Llama-1B/3B), enabling fast training and inference.
3. Unit of Decision Layer 7/7 usable papers
bargain: Each record is independently classified as proxy-processable or oracle-required based on whether its proxy score exceeds the cascade threshold ρ. Records with S(x) > ρ use the proxy answer; others use the oracle. The decision unit is a single record, and the threshold ρ is a global parameter determined by the sampling/estimation procedure.
thriftllm: The ensemble selection is performed per query class (cluster of semantically similar queries). At inference time, adaptive selection operates per query, pruning unnecessary LLM invocations based on real-time observations. The budget constraint is enforced strictly per query, unlike FrugalGPT's expected-cost approach.
nirvana: The physical optimizer makes model selection decisions at the per-operator granularity — each semantic operator in a logical plan is independently assigned its most cost-effective backend model. This is enabled by the Operator Independence Hypothesis (Hypothesis 1). The logical optimizer operates at the per-plan level, evaluating and comparing entire logical plans.
lotus: The unit of decision varies by operator: sem_filter and sem_map operate per-row; sem_join evaluates per-pair of rows; sem_topk performs pairwise comparisons between document pairs; sem_agg reasons over groups of rows. Each operator defines its own granularity of LM invocation.
csv: UniVote makes a uniform cluster-level decision: all unsampled tuples in a cluster receive the same label. SimVote makes per-tuple decisions by computing similarity-weighted scores for each individual unsampled tuple. Both operate at the cluster granularity for sampling but differ in label assignment granularity.
task_cascades: Each document is the unit of decision. At each cascade stage, the system processes a fraction fᵢ of the document (the top-fᵢ most relevant content after restructuring). The decision to accept or escalate is made per-document based on the model's class-specific confidence threshold τᵢᶜ.
scaledoc: Each document is independently assigned a decision score indicating likelihood of satisfying the boolean semantic predicate. The cascade then classifies each document individually as positive, negative, or ambiguous based on threshold comparison.
4. Predicate Transformation Layer 7/7 usable papers
bargain: The user's quality target (accuracy T, precision T, or recall T) is transformed into a series of hypothesis tests at candidate thresholds. For each candidate threshold ρ, BARGAIN tests whether the true quality metric (P_D(ρ), A_D(ρ), or R_D(ρ)) meets T using the estimation function E^BARGAIN. For BARGAIN_A-M, the accuracy target is decomposed into per-class accuracy targets with separate thresholds per class.
thriftllm: Rather than using a single LLM's response, ThriftLLM aggregates responses from multiple LLMs via a maximum-likelihood framework. The belief function h(C_k | ϕ_S) efficiently determines which class has the highest likelihood without computing exact likelihoods. This transforms the multi-model classification into a single aggregated prediction.
nirvana: The agentic logical optimizer transforms predicates/instructions through three rules: (1) Filter pushdown reorders operators to prune data early; (2) Operator fusion merges multiple operators into one with a combined NL predicate, reducing LLM calls; (3) Non-LLM replacement converts NL instructions into equivalent compute functions (e.g., 'Score > 8.5' becomes a comparison UDF). These transformations are expressed in natural language and applied by an LLM rewriter.
lotus: User-specified langex expressions are automatically wrapped in operator-specific instruction prompts managed by the system (e.g., the filter prompt instructs the model to output 'True' or 'False'). The system handles prompt construction transparently and can leverage prompt optimization techniques (e.g., DSPy). Demonstrations can be optionally provided.
csv: The NL predicate e is directly combined with tuple content and a system prompt to form the LLM input. For multi-class tasks (Airdialogue), the task is decomposed into multiple binary semantic filter queries (AD-Q1/Q2/Q3/Q4), each corresponding to one class. Additional task-specific instructions are prepended to the prompt.
task_cascades: The original operation is transformed into multiple surrogate operations—simpler, decomposed, or related operations whose output classes are a subset of the original. An agentic loop using o1-mini iteratively proposes surrogates informed by failure cases and hard examples from the current cascade. Examples include prerequisite checks (e.g., 'does the opinion mention a lower court?') and pattern-based heuristics. This is a key novel contribution beyond standard model cascades.
scaledoc: The natural language predicate is not decomposed but rather encoded alongside documents into a shared latent space via the contrastive learning framework. The predicate is transformed into a query embedding that serves as an anchor. Decision scores are cosine similarities in the learned space, designed to satisfy smoothness, semantic monotonicity, and bipolarity properties.
5. Calibration / Sampling Layer 7/7 usable papers
bargain: BARGAIN's adaptive sampling iterates through candidate thresholds in decreasing order, sampling records from D^ρ (records with proxy score > ρ) until the estimation function confirms the threshold meets the target. This contrasts with SUPG's importance sampling (based on proxy scores, ignoring the target) and the naive approach's uniform sampling. The anytime-valid property of the Waudby-Smith-Ramdas test allows repeated testing during sampling without error inflation. For RT queries, a positive density pre-filtering step uses binary search to focus sampling on regions with high positive density.
thriftllm: θ Monte Carlo simulations estimate prediction accuracy ξ(·) with parameters ε=0.1, δ=0.01. Success probabilities are estimated from historical data via DBSCAN clustering of query embeddings. When probabilities have confidence intervals, a median-of-means procedure (Lemma 10) diminishes failure probability to desired levels.
nirvana: Both the logical and physical optimizers use data samples (5% ratio) for evaluation. The logical optimizer executes candidate plans on samples and uses LLM-as-a-Judge to rate semantic equivalence. The physical optimizer computes improvement scores on sampled data to estimate model cost-effectiveness. Default constant selectivity assumptions (filter=0.5, reduce=0, others=1) are used for cost estimation, with plans for future semantic cardinality estimation.
lotus: For model cascades in sem_filter and sem_topk, LOTUS computes confidence scores by exponentiating the log-probabilities of the output tokens corresponding to True/False labels. A user-defined confidence threshold determines which records are routed to the oracle model. This is a lightweight, operator-semantics-aware scoring function.
csv: Within each cluster, tuples are sampled uniformly at random at rate ξ (default 5‰, minimum 101 samples). The theoretical analysis based on the Bernstein Inequality provides an explicit relationship between the error tolerance ε and the required sampling ratio ξ, enabling principled parameter tuning. The user specifies ε and the framework computes the necessary ξ.
task_cascades: Confidence scores are derived from LLM token-level log-probabilities transformed into class distributions p_m(c|x_f, o). Thresholds are first set per-task on the development set to achieve per-class accuracy ≥ α (Algorithm 2). A subsequent threshold adjustment procedure (Algorithm 3) uses a held-out validation split with the Waudby-Smith and Ramdas (2024) estimator to provide statistical guarantees. The development set is split into training (for cascade construction) and validation (for threshold adjustment), each with at least 75 documents.
scaledoc: ScaleDoc samples ~5% of documents via stratified sampling across score bins, labels them with the oracle, then reconstructs global positive/negative score distributions using jittering (for information recovery), linear interpolation density estimation, and moving average smoothing. This calibration enables accurate accuracy estimation for any threshold pair from a small sample.
6. Routing / Action Layer 7/7 usable papers
bargain: After determining the cascade threshold ρ*, records with proxy score > ρ* are routed to the proxy model and records with score ≤ ρ* are routed to the oracle model. For AT queries, sampled records during threshold determination are also labeled by the oracle. For PT/RT queries, the oracle budget k is split between sampling and final labeling. The selection procedure chooses the threshold maximizing utility (minimum ρ for PT/AT to maximize recall/minimize cost; maximum ρ for RT to maximize precision).
thriftllm: SurGreedyLLM selects the best ensemble among three candidates: greedy on ξ(·), greedy on surrogate γ(·), and the single best LLM. At query time, ThriftLLM's adaptive selection applies models sequentially and terminates early when the termination condition F(T*)·H_2(ϕ_S) ≤ H_1(ϕ_S) guarantees the prediction won't change, routing the query to fewer LLMs than the full ensemble.
nirvana: The physical optimizer uses a greedy algorithm (Algorithm 2) that iterates through models in order of increasing capability. For each operator, it computes the improvement score and selects the model if the marginal improvement exceeds threshold $\Delta I_{min}$ (set to 20%). The logical optimizer uses random walk search with a mixture sampling distribution to route between plan exploration and exploitation. Concurrent execution with up to 16 coroutines is used for throughput.
lotus: Records with confidence below the threshold are routed from the proxy to the oracle LM. For joins, the system selects among nested-loop, map-search-filter, or search-filter algorithms based on table size and user-specified LM call budget. For topk, the system chooses among quickselect, heap, or quadratic algorithms. Semantic index optimizations are applied when correlation exists between embeddings and the ranking criteria.
csv: Based on the voting score compared to thresholds ub and lb (default ub=0.85, lb=0.15), tuples are routed to one of three actions: (1) accepted as True if score ≥ ub, (2) rejected as False if score ≤ lb, (3) sent for recursive re-clustering if score ∈ (lb, ub). After maximum re-clustering depth (default 3), remaining ambiguous tuples fall back to direct LLM invocation.
task_cascades: Documents flow through an ordered sequence of tasks. At each stage, if the model's confidence exceeds the class-specific threshold, the prediction is accepted and the cascade terminates for that document. Otherwise, the document is escalated to the next task. The final fallback is always the oracle task (full document, original operation, oracle model). Task ordering is determined by a greedy algorithm inspired by approximation algorithms for Minimum Sum Set Cover, which sequentially adds the task that most reduces total inference cost while satisfying per-task accuracy constraints.
scaledoc: Documents with scores above upper threshold rb are classified positive; below lower threshold lb are classified negative; those in [lb, rb] are routed to the oracle LLM. Thresholds are selected via an efficient Pareto frontier traversal algorithm (Algorithm 2) that minimizes unfiltered rate subject to accuracy constraint, with linear complexity.
7. Guarantee Layer 7/7 usable papers
bargain: BARGAIN provides rigorous finite-sample guarantees: P(quality_metric ≥ T) ≥ 1-δ for user-specified target T and failure probability δ. This is achieved through: (1) Waudby-Smith-Ramdas anytime-valid tests (Lemma 2.1) providing tighter bounds than Hoeffding by incorporating empirical variance, (2) data-aware threshold selection (Lemma 3.5) with tolerance parameter η avoiding |C|-factor in failure probability, and (3) union bound across candidate thresholds. For RT queries with β>0, guarantees apply to the dense subset dense_β(D) rather than all of D. SUPG only provides asymptotic (CLT-based) guarantees that can fail with small samples.
thriftllm: ThriftLLM provides a data-dependent approximation guarantee (Theorem 8): with probability ≥ 1-δ, the solution achieves at least (ratio - ε)(1 - 1/√e) times the optimal prediction accuracy, where the ratio depends on the gap between ξ and γ on the selected sets. Extended to confidence interval estimates (Theorem 9) with failure probability δ + L²·Σδ_l. The budget constraint is strictly enforced per query.
nirvana: Nirvana provides approximate quality guarantees through: (1) an error tolerance ε (set to 0.8) that filters out plans whose LLM-as-a-Judge similarity score falls below the threshold; (2) an improvement margin ΔI_min (20%) for physical optimization. These are soft, empirical guarantees rather than formal statistical bounds. The LLM-as-a-Judge achieves >80% success rate but can fail in ~10% of cases. No formal probabilistic guarantees (e.g., confidence intervals) are provided.
lotus: LOTUS does not provide formal accuracy or recall guarantees. The system relies on empirical evaluation across applications to demonstrate quality. Approximate join algorithms trade off completeness for efficiency. The confidence threshold in cascades is user-specified without formal bounds on accuracy loss.
csv: CSV provides probabilistic error guarantees: Pr[f(t_i) ≠ x_i] ≤ max(lb + ε, 1 - (ub - ε)) with probability at least 1 - 2l^n (Theorems 3.3 and 3.6). The error bound explicitly connects to the sample ratio ξ, enabling users to trade off cost vs. accuracy. In the worst case, the framework falls back to full linear LLM invocation, ensuring bounded errors.
task_cascades: The system provides a guarantee that Pr(Acc(π*) < α) ≤ δ, where δ is user-specified (default 0.25). This is achieved via threshold adjustment on a validation split using the Waudby-Smith and Ramdas (2024) concentration inequality, which leverages both sample mean and variance for tighter bounds than Hoeffding's inequality. The procedure accounts for multiple hypothesis tests within the adjustment loop. If no cascade meets the guarantee, the system falls back to oracle-only processing.
scaledoc: Users specify an accuracy target α (e.g., 0.90). The system uses reconstructed score distributions to estimate accuracy for candidate thresholds. Empirical validation shows ScaleDoc meets α=0.90 in >80% of trials with worst-case accuracy loss of only 0.04. No formal statistical guarantee is provided; the guarantee is empirical via calibration.
