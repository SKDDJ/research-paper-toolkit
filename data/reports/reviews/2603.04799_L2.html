Beyond Linear LLM Invocation: An Efficient and Effective Semantic Filter Paradigm

PVLDB 2026 Level 2 Review

S Core Contribution

The paper proposes Clustering-Sampling-Voting (CSV), a new paradigm for LLM-powered semantic filter processing that reduces LLM invocations to sublinear complexity in the average case. CSV embeds tuples into semantic clusters offline, samples a small subset for LLM evaluation, and infers cluster-level labels via two voting strategies: UniVote (uniform majority voting) and SimVote (similarity-weighted voting), with theoretical error guarantees derived from the Bernstein Inequality that explicitly connect the error bound to the sample ratio. Section 1, Section 3

F Mapping to Dr. Lan's 7-Layer Semantic Filter Framework

1. Data Representation Layer

Tuples are embedded using E5-Large pretrained encoder into vector representations. For long texts exceeding context length, text is segmented into chunks and the final embedding is the mean of segment embeddings. Optionally, BM25 scores are combined with Euclidean distance via parameter α for lexically-anchored predicates. Embeddings are generated offline and are query-agnostic. Section 3.1, Section 4.1

2. Candidate Executor / Proxy Layer

Unlike Lotus and BARGAIN which use a smaller proxy LLM (e.g., LLaMA-3.2-3B) for initial filtering, CSV replaces per-tuple proxy LLM calling with embedding-based grouping. The embedding model serves as the cheap proxy, and only a single LLM (e.g., LLaMA-3.1-8B) is used for sampled tuples. This avoids the linear proxy scan bottleneck entirely. Section 3, Section 2.2

3. Unit of Decision Layer

UniVote makes a uniform cluster-level decision: all unsampled tuples in a cluster receive the same label. SimVote makes per-tuple decisions by computing similarity-weighted scores for each individual unsampled tuple. Both operate at the cluster granularity for sampling but differ in label assignment granularity. Section 3.1, Algorithms 2 and 3

4. Predicate Transformation Layer

The NL predicate e is directly combined with tuple content and a system prompt to form the LLM input. For multi-class tasks (Airdialogue), the task is decomposed into multiple binary semantic filter queries (AD-Q1/Q2/Q3/Q4), each corresponding to one class. Additional task-specific instructions are prepended to the prompt. Section 2.1, Section 4.1 (Queries)

5. Calibration / Sampling Layer

Within each cluster, tuples are sampled uniformly at random at rate ξ (default 5‰, minimum 101 samples). The theoretical analysis based on the Bernstein Inequality provides an explicit relationship between the error tolerance ε and the required sampling ratio ξ, enabling principled parameter tuning. The user specifies ε and the framework computes the necessary ξ. Section 3.2, Theorems 3.3 and 3.6

6. Routing / Action Layer

Based on the voting score compared to thresholds ub and lb (default ub=0.85, lb=0.15), tuples are routed to one of three actions: (1) accepted as True if score ≥ ub, (2) rejected as False if score ≤ lb, (3) sent for recursive re-clustering if score ∈ (lb, ub). After maximum re-clustering depth (default 3), remaining ambiguous tuples fall back to direct LLM invocation. Section 3.1, Algorithm 1 lines 16-20

7. Guarantee Layer

CSV provides probabilistic error guarantees: Pr[f(t_i) ≠ x_i] ≤ max(lb + ε, 1 - (ub - ε)) with probability at least 1 - 2l^n (Theorems 3.3 and 3.6). The error bound explicitly connects to the sample ratio ξ, enabling users to trade off cost vs. accuracy. In the worst case, the framework falls back to full linear LLM invocation, ensuring bounded errors. Section 3.2, Theorems 3.3 and 3.6

M Method Components
Offline Clustering

All tuples in a relation are embedded using a pretrained encoder (e.g., E5-Large) and grouped into semantically similar clusters using K-means. This step is performed offline and is query-agnostic, reusable across different predicates. Optionally, BM25 scores are combined with embedding Euclidean distance via a weighting parameter α for predicates with strong lexical anchoring. Section 3.1, Algorithm 1 lines 2-3

Online Sampling

Within each cluster, a small sample of tuples is drawn uniformly at a sampling rate ξ (with a minimum sample size min_sample=101) and evaluated with the LLM as representatives. The sampling ratio directly controls the trade-off between LLM invocation cost and theoretical error. Section 3.1, Algorithm 1 lines 9-15

UniVote (Uniform Voting)

UniVote computes the ratio of sampled tuples that pass the filter and compares it against two thresholds ub and lb. If the ratio ≥ ub, all remaining tuples in the cluster are labeled True; if ≤ lb, all are labeled False; otherwise, tuples are marked as undetermined and sent for re-clustering. Section 3.1, Algorithm 2

SimVote (Similarity-based Voting)

SimVote computes a per-tuple score by aggregating sampled tuple labels weighted by normalized semantic similarity between the target tuple and each sampled tuple. This provides fine-grained, per-tuple decisions rather than uniform cluster-level labels, offering more robustness when initial clustering does not perform well. Section 3.1, Algorithm 3, Eq. 4

Recursive Re-clustering

When a cluster's voting score falls in the ambiguous interval (lb, ub), the framework triggers online re-clustering on the undetermined tuples. This recursive mechanism continues until a maximum split limit (default 3 iterations) is reached, after which remaining ambiguous tuples fall back to direct LLM invocation. Section 3.1, Algorithm 1 lines 18-20

Hybrid Distance Metric

For predicates with strong lexical anchoring, a hybrid clustering distance combines BM25 similarity (lexical) and Euclidean distance (semantic) via a weighting parameter α, improving clustering quality for explicit and hybrid predicates. Section 4.1

Q Key Formulas
Eq. 1 Section 2.1
\[\sigma_{M(e)}(T) = \{t \in T \mid M(t, e) = \text{True}\}\]
Definition of the semantic filter operator: returns all tuples in T whose textual attributes satisfy the NL predicate e by LLM judgment.
Eq. 3 Section 3.1
\[\hat{M}(t_i; e) = \begin{cases} \text{True} & \text{if score}(t_i) \geq ub \\ \text{False} & \text{if score}(t_i) \leq lb \\ \text{Undetermined} & \text{if score}(t_i) \in (lb, ub) \end{cases}\]
Voting decision rule based on thresholds ub and lb for both UniVote and SimVote.
Eq. 4 Section 3.1
\[\text{score}(t_i) = \sum_{t_j \in C'} \frac{\text{sim}(e_i, e_j)}{\sum_{t_k \in C'} \text{sim}(e_i, e_k)} \mathbb{I}(M(t_j, e)), \forall t_i \in C \setminus C'\]
SimVote scoring function: similarity-weighted aggregation of sampled tuple labels for each unsampled tuple.
Eq. 7 (UniVote ξ bound) Theorem 3.3
\[\xi \geq \frac{1}{2} - \sqrt{\frac{1}{4} + \ln l \left(\frac{2\hat{\sigma}^2}{\epsilon^2} + \frac{2}{3\epsilon}\right)}\]
Minimum sampling ratio for UniVote to guarantee error bound ε with failure probability controlled by l.
Eq. 12 (SimVote ξ bound) Theorem 3.6
\[\xi \geq \frac{1}{2} - \sqrt{\frac{1}{4} + \frac{v \ln l (6\hat{\sigma}^2 + 2\epsilon)}{3\epsilon^2}}\]
Minimum sampling ratio for SimVote to guarantee error bound ε, incorporating weight variance factor v.
Eq. 8 (Error bound) Theorem 3.3
\[Pr[f(t_i) \neq x_i] \leq \max(lb + \epsilon, 1 - (ub - \epsilon))\]
Probabilistic error bound for UniVote: the probability that the voting decision disagrees with the true LLM output.

A Assumptions
Explicit Semantically similar inputs (tuples close in embedding space) tend to elicit consistent outputs from LLMs. Section 3, Figure 2
Explicit The system prompt and predicate expression are identical for all tuples in a given filter query; only the tuple content varies, so variability in LLM output is fully driven by the tuple. Section 3
Explicit For SimVote's Lemma 3.5, the sampling is uniform from the cluster, which allows the mean of similarity-weighted scores to equal the mean of sampled labels. Lemma 3.5
Implicit Clusters produced by K-means on embeddings will be sufficiently pure (dominated by a single label) for most predicates. Section 3.1, Figure 1
Implicit The LLM's binary output for each tuple is treated as a fixed ground truth (x_i = I(M(t_i, e))) for the theoretical analysis, ignoring LLM stochasticity. Section 3.2
