S Core Contribution

ScaleDoc introduces an offline-online decoupled architecture for semantic predicate execution over large document collections. It pre-computes LLM-based semantic embeddings offline, then trains a query-aware lightweight proxy model using a novel contrastive learning framework (with three loss functions ensuring smoothness, semantic monotonicity, and bipolarity) to produce well-behaved decision scores. An adaptive cascade mechanism with stratified sampling, distribution reconstruction, and frontier-based threshold selection minimizes oracle LLM invocations while meeting user-specified accuracy targets. Section 1, Section 2.2

F Mapping to Dr. Lan's 7-Layer Semantic Filter Framework

1. Data Representation Layer

ScaleDoc uses NvEmbed (derived from Mistral-7B) to generate dense semantic embeddings for each document in a one-time offline phase. These embeddings capture rich contextual semantics and are stored for reuse across all ad-hoc queries, eliminating redundant per-query document processing. Section 2.2, Section 6.1

2. Candidate Executor / Proxy Layer

The proxy is a query-specific 3-layer MLP trained online via contrastive learning on pre-computed embeddings. It produces cosine similarity decision scores. The oracle is GPT-4o accessed via API. The proxy is extremely lightweight compared to LLM cascade proxies (Llama-1B/3B), enabling fast training and inference. Section 3.2, Section 5, Section 6.1

3. Unit of Decision Layer

Each document is independently assigned a decision score indicating likelihood of satisfying the boolean semantic predicate. The cascade then classifies each document individually as positive, negative, or ambiguous based on threshold comparison. Section 2.1, Section 4.1

4. Predicate Transformation Layer

The natural language predicate is not decomposed but rather encoded alongside documents into a shared latent space via the contrastive learning framework. The predicate is transformed into a query embedding that serves as an anchor. Decision scores are cosine similarities in the learned space, designed to satisfy smoothness, semantic monotonicity, and bipolarity properties. Section 3.1, Section 3.2

5. Calibration / Sampling Layer

ScaleDoc samples ~5% of documents via stratified sampling across score bins, labels them with the oracle, then reconstructs global positive/negative score distributions using jittering (for information recovery), linear interpolation density estimation, and moving average smoothing. This calibration enables accurate accuracy estimation for any threshold pair from a small sample. Section 4.2, Algorithm 1

6. Routing / Action Layer

Documents with scores above upper threshold rb are classified positive; below lower threshold lb are classified negative; those in [lb, rb] are routed to the oracle LLM. Thresholds are selected via an efficient Pareto frontier traversal algorithm (Algorithm 2) that minimizes unfiltered rate subject to accuracy constraint, with linear complexity. Section 4.1, Section 4.3, Algorithm 2

7. Guarantee Layer

Users specify an accuracy target α (e.g., 0.90). The system uses reconstructed score distributions to estimate accuracy for candidate thresholds. Empirical validation shows ScaleDoc meets α=0.90 in >80% of trials with worst-case accuracy loss of only 0.04. No formal statistical guarantee is provided; the guarantee is empirical via calibration. Section 4.2, Section 6.5, Figure 10(a)

M Method Components
Offline Representation Phase

A one-time compute-intensive phase where a small-scale LLM (e.g., NvEmbed derived from Mistral-7B) generates semantic embeddings for each document. These embeddings are stored and reused across all ad-hoc queries, eliminating redundant document-level LLM processing. Section 2.2

Query-Aware Proxy Model

A lightweight 3-layer MLP encoder $E(\cdot)$ trained online for each ad-hoc query using contrastive learning. It maps pre-computed document and query embeddings into a shared latent space, producing cosine similarity decision scores. Training uses a small oracle-labeled sample (~5-10%). Section 3.2

Two-Phase Contrastive Training

Phase 1 uses $\mathcal{L}_{qsim}$ (DPR-inspired contrastive loss) to establish semantic monotonicity by pulling positive documents closer to the query anchor. Phase 2 uses $\mathcal{L}_{supcon}$ (supervised contrastive loss for intra-class clustering) and a novel $\mathcal{L}_{polar}$ (bellwether-guided polar loss) to enforce bipolarity — clear separation between positive and negative score distributions. Section 3.2

Bellwether Polar Loss (L_polar)

A novel loss function that selects bellwether samples — the closest positive and furthest negative to the query in each mini-batch — as anchors. It pulls all positives toward the positive bellwether and all negatives toward the negative bellwether, explicitly enlarging the separation margin between classes. Section 3.2

Ad-hoc Calibration Workflow

Reconstructs global score distributions from a small labeled sample via three steps: (1) stratified sampling to preserve density across score bins, (2) jittering for information recovery in low-density regions, (3) linear interpolation density estimation followed by moving average smoothing to produce robust continuous PDFs for positive and negative classes. Section 4.2, Algorithm 1

Frontier-Based Threshold Selection

An efficient algorithm that solves the constrained optimization problem (minimize unfiltered rate subject to accuracy target) by tracing the Pareto frontier of feasible threshold pairs. Reduces complexity from quadratic to linear in the number of discretization steps. Section 4.3, Algorithm 2

Training Set Rebalancing

A fallback-style rebalancing method that augments minority class samples by adding Gaussian noise to existing minority class embeddings when class imbalance is detected in the initial sample. Section 5

Bound The frontier-based threshold selection algorithm reduces complexity from quadratic to linear with respect to the number of discretization steps, and the optimal solution lies on the Pareto-frontier of the feasible set defined by the accuracy constraint. Section 4.3
Q Key Formulas
Eq. 1 Section 3.2
\[\mathcal{L}_{qsim}(q,\{d^{+}_{i}\}_{i=1}^{m},\{d^{-}_{j}\}_{j=1}^{n-m})=-\log\frac{\sum_{i=1}^{m}{e^{\text{sim}(q,d^{+}_{i})/\tau}}}{\sum_{j=1}^{n-m}{e^{\text{sim}(q,d^{-}_{j})/\tau}+\sum_{i=1}^{m}{e^{\text{sim}(q,d^{+}_{i})/\tau}}}}\]
Query-similarity contrastive loss (Phase 1) that pulls positive documents closer to the query while pushing negatives away, establishing semantic monotonicity.
Eq. 2 Section 3.2
\[\mathcal{L}_{supcon}(\{d_{i}\})=-\sum_{i=1}^{n}\frac{1}{|U(i)|}\log\frac{\sum_{d_{p}\in U(i)}e^{\text{sim}(d_{i},d_{p})/\tau}}{\sum_{d_{k}\in A(i)}e^{\text{sim}(d_{i},d_{k})/\tau}}\]
Supervised contrastive loss (Phase 2) that encourages intra-class clustering by pulling same-label documents together.
Eq. 3 Section 3.2
\[\mathcal{L}_{polar}(q,\{d^{+}_{i}\}_{i=1}^{m},\{d^{-}_{j}\}_{j=1}^{n-m})=-(\log\frac{\sum_{i=1}^{m}{e^{\text{sim}(d_{pos},d^{+}_{i})/\tau}}}{\sum_{j=1}^{n-m}{e^{\text{sim}(d_{pos},d^{-}_{j})/\tau}+\sum_{i=1}^{m}{e^{\text{sim}(d_{pos},d^{+}_{i})/\tau}}}}+\log\frac{\sum_{i=1}^{n-m}{e^{\text{sim}(d_{neg},d^{-}_{i})/\tau}}}{\sum_{j=1}^{n-m}{e^{\text{sim}(d_{neg},d^{-}_{j})/\tau}+\sum_{i=1}^{m}{e^{\text{sim}(d_{neg},d^{+}_{i})/\tau}}}}})\]
Novel bellwether polar loss (Phase 2) that uses bellwether anchors to explicitly enforce bipolar separation between positive and negative document clusters.
Eq. 4 Section 4.1
\[u(lb,rb)=\frac{|\{s_{i}\in S(W)\mid lb\leq s_{i}\leq rb\}|}{|S(W)|}\]
Unfiltered rate — the fraction of documents sent to the oracle LLM, controlled by lower and upper thresholds.
Eq. 5 Section 4.1
\[\min_{(lb,rb)\in\mathcal{K}}u(lb,rb)\quad\text{s.t.}\;\text{Acc}(lb,rb)\geq\alpha\]
Constrained optimization problem: minimize unfiltered rate while meeting user-specified accuracy target α.
Phase 2 Joint Loss Section 5
\[\mathcal{L}_{2}=\lambda\cdot\mathcal{L}_{supcon}+(1-\lambda)\cdot\mathcal{L}_{polar}\]
Joint loss for Training Phase 2, with λ=0.2 empirically balancing supervised contrastive and polar losses.

A Assumptions
Explicit The oracle LLM (GPT-4o) provides ground-truth labels — its predictions are treated as the gold standard for accuracy measurement. Section 6.1
Explicit Documents can be meaningfully represented as fixed-dimensional semantic embeddings that capture sufficient information for predicate evaluation. Section 2.2
Explicit The offline embedding phase is a one-time cost that is amortized across many ad-hoc queries, making it acceptable. Section 2.2, Section 6.2
Explicit A small sample (~5-10%) is sufficient to train the proxy model and calibrate the cascade for each query. Section 5, Section 6.6
Explicit The score distributions produced by the contrastive learning framework exhibit monotonic properties that enable the frontier-based threshold selection algorithm to find optimal solutions. Section 4.3
Explicit Boolean (binary) semantic predicates are the target workload — multi-class or continuous-valued predicates are not addressed. Section 2.1
L Limitations
Author-stated The accuracy guarantee is empirical (>80% of trials meet target) rather than providing formal statistical guarantees like SUPG's theoretical bounds. Section 6.5
Author-stated Formal proofs of optimality for the threshold selection algorithm are deferred to an extended version. Section 4.3
Inferred The system is evaluated only on collections of 10,000 documents; scalability to millions of documents (as mentioned in motivation) is not directly demonstrated. Section 6.1
Author-stated The offline embedding phase requires a one-time LLM inference pass over all documents, which may be costly for very large corpora. Section 6.2
Inferred Only boolean semantic predicates are supported; more complex semantic operators (join, aggregation) are not addressed. Section 2.1
Inferred The proxy model must be retrained for each new ad-hoc query, adding per-query overhead. Section 3.2
