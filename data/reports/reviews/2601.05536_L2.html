S Core Contribution

The paper introduces task cascades, a framework that generalizes model cascades by allowing each cascade stage to vary not only the model but also the surrogate operation and the document fraction processed. An agentic loop iteratively discovers surrogate operations, a lightweight relevance classifier restructures documents to front-load relevant content, and a greedy cascade assembly algorithm (motivated by NP-hardness via reduction from Minimum Sum Set Cover) constructs cost-optimal cascades with optional statistical accuracy guarantees. Section 1, Section 2

F Mapping to Dr. Lan's 7-Layer Semantic Filter Framework

1. Data Representation Layer

Documents are segmented into fixed-granularity chunks, each scored by a lightweight logistic regression classifier trained on oracle-labeled relevance data using text-embedding-3-small embeddings. Chunks are reordered so the most relevant content appears first, enabling efficient prefix-based fractional processing at fractions f ∈ {0.1, 0.25, 0.5, 1.0}. Section 4

2. Candidate Executor / Proxy Layer

The framework uses a cheap proxy model (GPT-4o-mini, ~17× cheaper) and an expensive oracle (GPT-4o). Both models are used to execute candidate tasks at various document fractions. The framework generalizes to any number of models but experiments focus on the two-model setting. An LLM agent (o1-mini) is used separately for surrogate operation generation. Section 2.2, Section 7.1.4

3. Unit of Decision Layer

Each document is the unit of decision. At each cascade stage, the system processes a fraction fᵢ of the document (the top-fᵢ most relevant content after restructuring). The decision to accept or escalate is made per-document based on the model's class-specific confidence threshold τᵢᶜ. Section 2.1

4. Predicate Transformation Layer

The original operation is transformed into multiple surrogate operations—simpler, decomposed, or related operations whose output classes are a subset of the original. An agentic loop using o1-mini iteratively proposes surrogates informed by failure cases and hard examples from the current cascade. Examples include prerequisite checks (e.g., 'does the opinion mention a lower court?') and pattern-based heuristics. This is a key novel contribution beyond standard model cascades. Section 5

5. Calibration / Sampling Layer

Confidence scores are derived from LLM token-level log-probabilities transformed into class distributions p_m(c|x_f, o). Thresholds are first set per-task on the development set to achieve per-class accuracy ≥ α (Algorithm 2). A subsequent threshold adjustment procedure (Algorithm 3) uses a held-out validation split with the Waudby-Smith and Ramdas (2024) estimator to provide statistical guarantees. The development set is split into training (for cascade construction) and validation (for threshold adjustment), each with at least 75 documents. Section 3.2.1, Section 3.2.3, Section 3.2.4

6. Routing / Action Layer

Documents flow through an ordered sequence of tasks. At each stage, if the model's confidence exceeds the class-specific threshold, the prediction is accepted and the cascade terminates for that document. Otherwise, the document is escalated to the next task. The final fallback is always the oracle task (full document, original operation, oracle model). Task ordering is determined by a greedy algorithm inspired by approximation algorithms for Minimum Sum Set Cover, which sequentially adds the task that most reduces total inference cost while satisfying per-task accuracy constraints. Section 3.2.2, Section 3.1

7. Guarantee Layer

The system provides a guarantee that Pr(Acc(π*) < α) ≤ δ, where δ is user-specified (default 0.25). This is achieved via threshold adjustment on a validation split using the Waudby-Smith and Ramdas (2024) concentration inequality, which leverages both sample mean and variance for tighter bounds than Hoeffding's inequality. The procedure accounts for multiple hypothesis tests within the adjustment loop. If no cascade meets the guarantee, the system falls back to oracle-only processing. Section 3.2.3, Theorem 3.2, Appendix A

M Method Components
Task Cascade Framework

A task cascade is an ordered sequence of tasks π = (T₁, T₂, …, Tₖ), where each task Tᵢ = (mᵢ, oᵢ, fᵢ, τᵢ) specifies a model, an operation (original or surrogate), a document fraction, and class-specific confidence thresholds. Documents are processed sequentially through tasks; if confidence exceeds the threshold, the prediction is accepted; otherwise, the document is escalated. This generalizes model cascades which only vary the model. Section 2.1

Greedy Cascade Assembly

Given a set of candidate task configurations, the algorithm greedily adds the task that most reduces total inference cost while maintaining per-task accuracy at or above the target α on its assigned subset of documents. This is motivated by the NP-hardness of optimal task ordering (Theorem 3.1), proven via reduction from Minimum Sum Set Cover. Section 3.2.2

Threshold Selection and Filtering

For each candidate task, the system finds the lowest confidence threshold per class such that predictions above the threshold achieve the target accuracy α. Tasks that cannot confidently classify at least g=10% of the development set are discarded. Section 3.2.1

Threshold Adjustment for Statistical Guarantees

A post-processing step that adjusts confidence thresholds using a validation split to ensure the cascade meets the accuracy target α with failure probability at most δ. Uses an estimator from Waudby-Smith and Ramdas (2024) that leverages both sample mean and variance for tighter bounds than Hoeffding's inequality. Thresholds are iteratively relaxed from conservative to less conservative using a shift index strategy. Section 3.2.3, Section 3.2.4

Document Restructuring

Documents are reordered so that the most relevant content for the original operation appears first, enabling prefix caching cost savings. A lightweight logistic regression classifier is trained on oracle-labeled chunk relevance data (using text-embedding-3-small embeddings) to score and rank document chunks. Chunk granularity is determined by asking the oracle to identify minimal line ranges needed to answer the operation. Section 4

Surrogate Operation Generation (Agentic Loop)

An LLM agent (o1-mini) iteratively proposes surrogate operations—simpler or decomposed variants of the original operation whose output classes are a subset of the original. The agent receives failure cases (documents reaching the oracle), hard examples, and summary statistics from the current cascade. Each surrogate is paired with all models and document fractions to create new candidate tasks. The loop runs for nₐ=3 iterations with nₛ=5 surrogates per iteration. Section 5

Cost Model with Prefix Caching

The cost model accounts for prefix caching offered by LLM APIs (50% discount on cached tokens). Documents are placed before operations in prompts to maximize cache reuse across tasks using the same model. The total cost includes new input tokens, cached input tokens, and operation tokens. Section 2.1, Section 6

T Theoretical Results
Theorem Constructing an optimal task cascade is NP-Hard, proven via reduction from Minimum Sum Set Cover (MSSC). The hardness holds even with a single proxy model and full documents (f=1). Theorem 3.1, Section 3.1
Theorem For any monotonic adjustment strategy ε and appropriate estimator E, Algorithm 3 returns a cascade π* with Pr(Acc(π*) < α) ≤ δ. Theorem 3.2, Section 3.2.3

Explicit The oracle model (GPT-4o) provides the ground truth labels; accuracy is measured relative to the oracle, not human annotations. Section 2.1
Explicit LLM APIs support prefix caching with a 50% discount on cached tokens, and documents are placed before operations in prompts to maximize cache utilization. Section 2.1
Explicit The output space is a fixed set of classes (classification setting). Extension to open-ended generation requires a reliable automatic evaluator. Section 2.1
Explicit LLM token-level log-probabilities are available and can be used as confidence scores. Section 2.1
Explicit A two-model setting (one proxy, one oracle) is sufficient; the framework generalizes to more models but experiments use only two. Section 2.2
