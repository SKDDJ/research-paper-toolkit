S Core Contribution

Nirvana is a multi-modal data analytics framework that introduces an agentic logical plan optimizer using natural-language transformation rules and random-walk-based search to explore semantically equivalent query plans, combined with a cost-aware physical plan optimizer that selects the most cost-effective LLM backend per operator using a novel improvement score metric. The physical optimizer further incorporates computation reuse and evaluation pushdown techniques guided by a model capability hypothesis to eliminate unnecessary expensive model invocations. Section 1, Section 2.2

F Mapping to Dr. Lan's 7-Layer Semantic Filter Framework

1. Data Representation Layer

Nirvana supports tables with both structured fields (numerical, dates) and unstructured fields (text, documents, images, audio). Unstructured fields are stored as file paths pointing to remote locations (URLs, S3). Semantic operators process these multi-modal fields via LLM inference. The data model is a generalization of relational tables to accommodate heterogeneous content. Section 2.1

2. Candidate Executor / Proxy Layer

The system uses a pool of models ordered by capability and cost: gpt-4.1-nano (cheapest/weakest), gpt-4o-mini, gpt-4.1-mini, gpt-4.1 (most expensive/strongest). The physical optimizer selects per-operator backends. Additionally, the logical optimizer can replace LLM operators entirely with non-LLM compute functions (UDFs), bypassing LLM inference altogether. Section 4, Section 3.2, Section 5.1.4

3. Unit of Decision Layer

The physical optimizer makes model selection decisions at the per-operator granularity — each semantic operator in a logical plan is independently assigned its most cost-effective backend model. This is enabled by the Operator Independence Hypothesis (Hypothesis 1). The logical optimizer operates at the per-plan level, evaluating and comparing entire logical plans. Section 4.1

4. Predicate Transformation Layer

The agentic logical optimizer transforms predicates/instructions through three rules: (1) Filter pushdown reorders operators to prune data early; (2) Operator fusion merges multiple operators into one with a combined NL predicate, reducing LLM calls; (3) Non-LLM replacement converts NL instructions into equivalent compute functions (e.g., 'Score > 8.5' becomes a comparison UDF). These transformations are expressed in natural language and applied by an LLM rewriter. Section 3.2

5. Calibration / Sampling Layer

Both the logical and physical optimizers use data samples (5% ratio) for evaluation. The logical optimizer executes candidate plans on samples and uses LLM-as-a-Judge to rate semantic equivalence. The physical optimizer computes improvement scores on sampled data to estimate model cost-effectiveness. Default constant selectivity assumptions (filter=0.5, reduce=0, others=1) are used for cost estimation, with plans for future semantic cardinality estimation. Section 3.1, Section 5.1.4

6. Routing / Action Layer

The physical optimizer uses a greedy algorithm (Algorithm 2) that iterates through models in order of increasing capability. For each operator, it computes the improvement score and selects the model if the marginal improvement exceeds threshold $\Delta I_{min}$ (set to 20%). The logical optimizer uses random walk search with a mixture sampling distribution to route between plan exploration and exploitation. Concurrent execution with up to 16 coroutines is used for throughput. Section 4.1, Section 3.1, Section 5.1.4

7. Guarantee Layer

Nirvana provides approximate quality guarantees through: (1) an error tolerance ε (set to 0.8) that filters out plans whose LLM-as-a-Judge similarity score falls below the threshold; (2) an improvement margin ΔI_min (20%) for physical optimization. These are soft, empirical guarantees rather than formal statistical bounds. The LLM-as-a-Judge achieves >80% success rate but can fail in ~10% of cases. No formal probabilistic guarantees (e.g., confidence intervals) are provided. Section 3.1, Section 5.1.4, Section 5.3.5

M Method Components
Agentic Logical Plan Optimizer

Uses an LLM-driven random walk search framework to explore a tree of candidate logical plans. Plans are sampled from a mixture of uniform and cost-weighted probability distributions (Eq. 1), rewritten by an LLM using natural language transformation rules (filter pushdown, operator fusion, non-LLM replacement), and evaluated via LLM-as-a-Judge for semantic equivalence checking. The optimizer iterates N_max times and returns the lowest-cost plan satisfying an accuracy constraint ε. Section 3

Transformation Rules

Three NL-specified rules: (1) Filter pushdown moves filters earlier in the plan; (2) Operator fusion merges multiple operators on the same field into one, reducing LLM calls; (3) Non-LLM replacement substitutes LLM-powered operators with equivalent compute functions (UDFs). Rules are expressed in natural language and decoupled from system internals. Section 3.2

LLM-as-a-Judge Plan Evaluator

Executes both the original and rewritten plans on a data sample, then prompts an LLM to rate semantic similarity on a 0-10 scale. The normalized rating serves as the plan's accuracy estimate. Achieves >80% success rate, >85% precision, and >90% recall across benchmarks. Section 3.1, Section 5.3.5

Physical Plan Optimizer with Improvement Score

Assigns the most cost-effective LLM backend to each operator in a logical plan. Uses a novel improvement score $I_{m_1 \rightarrow m}$ that measures the expected proportion of inputs where switching from baseline model $m_1$ to model $m$ yields outputs consistent with the oracle model $m^*$ while $m_1$ does not. Models are evaluated in order of increasing capability, and a model is selected if its improvement score exceeds a threshold $\Delta I_{min}$. Section 4

Evaluation Pushdown

Reduces expensive oracle model ($m^*$) invocations by conditioning evaluations on subsets where cheaper models disagree. Analogous to predicate pushdown in databases — expensive evaluations $m_2 = m^*$ are only computed on records where $m_1 \neq m_2$. Section 4.2

Computation Reuse

When computing improvement scores for progressively stronger models, reuses intermediate results from earlier computations. E.g., $I_{m_1 \rightarrow m_3}$ directly reuses $I_{m_1 \rightarrow m_2}$ via the law of total probability decomposition. Section 4.2

Model Capability Hypothesis

Hypothesis 2 states that if a weaker model $m$ returns the correct answer, any stronger model $m^+$ also returns the correct answer. This enables elimination of expensive $m^*$ invocations when computing improvement scores, yielding approximations (Eqs. 6-8) that avoid oracle calls entirely in many cases. Empirically validated: >90% of disagreements between GPT-4.1 and GPT-4.1-nano favor GPT-4.1. Section 4.3, Table 2

Local Rewrite Model

A fine-tuned small LLM (e.g., Qwen-3-8B, LLaMA-3-8B) trained on pairs of un-optimized and rewritten logical plans using LoRA, serving as a local substitute for cloud LLM services during plan rewriting to reduce latency and cost. Section 3.3

Semantic Operators

Four programmable operators: map (LLM-driven column transformation), filter (NL predicate evaluation), reduce (NL-specified aggregation), and rank (NL-defined ranking). All parameterized by natural language instructions and applicable to multi-modal data. Section 2.1, Table 1
