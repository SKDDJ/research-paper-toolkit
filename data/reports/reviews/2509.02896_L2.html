Cut Costs, Not Accuracy: LLM-Powered Data Processing with Guarantees

arXiv preprint 2025 Level 2 Review
Sepanta Zeighami, Shreya Shankar, Aditya Parameswaran
UC Berkeley
arXiv PDF
S Core Contribution

BARGAIN is a method for LLM-powered data processing using model cascades that employs a novel adaptive sampling strategy and variance-aware statistical estimation procedure (building on anytime-valid hypothesis tests by Waudby-Smith and Ramdas) to set cascade thresholds with rigorous theoretical guarantees on accuracy, precision, or recall. Unlike prior work (SUPG) that provides only asymptotic guarantees via CLT, BARGAIN provides finite-sample guarantees while achieving significantly better utility by exploiting data and task characteristics, including the observation that sample variance decreases as quality increases. Section 1, Section 3

F Mapping to Dr. Lan's 7-Layer Semantic Filter Framework

1. Data Representation Layer

Each record x_i in dataset D has an oracle output O(x_i), a proxy output P(x_i), and a proxy score S(x_i) ∈ [0,1] representing the proxy's confidence. For binary classification (PT/RT), proxy scores represent confidence in the positive class. For multi-class (AT), proxy scores represent confidence in the predicted class. Records are ordered/grouped by proxy scores for threshold-based decisions. Section 2.1, Section 2.2

2. Candidate Executor / Proxy Layer

The system uses a model cascade with an expensive oracle model (e.g., GPT-4o, Claude Sonnet) and a cheap proxy model (e.g., GPT-4o-mini, Claude Haiku). The proxy cost is assumed negligible relative to the oracle (>10× cost difference). The proxy provides both outputs and confidence scores (e.g., logprobabilities). Extensions to multiple proxies are discussed in Section D. Section 2.1, Section 1

3. Unit of Decision Layer

Each record is independently classified as proxy-processable or oracle-required based on whether its proxy score exceeds the cascade threshold ρ. Records with S(x) > ρ use the proxy answer; others use the oracle. The decision unit is a single record, and the threshold ρ is a global parameter determined by the sampling/estimation procedure. Section 2.2, Figure 1

4. Predicate Transformation Layer

The user's quality target (accuracy T, precision T, or recall T) is transformed into a series of hypothesis tests at candidate thresholds. For each candidate threshold ρ, BARGAIN tests whether the true quality metric (P_D(ρ), A_D(ρ), or R_D(ρ)) meets T using the estimation function E^BARGAIN. For BARGAIN_A-M, the accuracy target is decomposed into per-class accuracy targets with separate thresholds per class. Section 3.1, Section 4.1.3

5. Calibration / Sampling Layer

BARGAIN's adaptive sampling iterates through candidate thresholds in decreasing order, sampling records from D^ρ (records with proxy score > ρ) until the estimation function confirms the threshold meets the target. This contrasts with SUPG's importance sampling (based on proxy scores, ignoring the target) and the naive approach's uniform sampling. The anytime-valid property of the Waudby-Smith-Ramdas test allows repeated testing during sampling without error inflation. For RT queries, a positive density pre-filtering step uses binary search to focus sampling on regions with high positive density. Section 3.3, Section 4.2.2

6. Routing / Action Layer

After determining the cascade threshold ρ*, records with proxy score > ρ* are routed to the proxy model and records with score ≤ ρ* are routed to the oracle model. For AT queries, sampled records during threshold determination are also labeled by the oracle. For PT/RT queries, the oracle budget k is split between sampling and final labeling. The selection procedure chooses the threshold maximizing utility (minimum ρ for PT/AT to maximize recall/minimize cost; maximum ρ for RT to maximize precision). Section 2.2, Section 3.2.2, Section 4.2.1

7. Guarantee Layer

BARGAIN provides rigorous finite-sample guarantees: P(quality_metric ≥ T) ≥ 1-δ for user-specified target T and failure probability δ. This is achieved through: (1) Waudby-Smith-Ramdas anytime-valid tests (Lemma 2.1) providing tighter bounds than Hoeffding by incorporating empirical variance, (2) data-aware threshold selection (Lemma 3.5) with tolerance parameter η avoiding |C|-factor in failure probability, and (3) union bound across candidate thresholds. For RT queries with β>0, guarantees apply to the dense subset dense_β(D) rather than all of D. SUPG only provides asymptotic (CLT-based) guarantees that can fail with small samples. Lemma 3.3, Lemma 3.4, Lemma 3.5, Lemma 3.6, Section 4.2.2

M Method Components
Variance-Aware Estimation Function (E^BARGAIN)

Replaces naive Hoeffding-based estimation with a hypothesis testing approach using results from Waudby-Smith and Ramdas [43] that incorporates empirical variance into the test statistic. The key insight is that the variance of observed precision decreases as true precision increases (Eq. 20), so E^BARGAIN provides increasingly tighter estimates for high-quality thresholds. The estimation function tests whether the true mean of indicator random variables exceeds the target T using an anytime-valid martingale-based test. Section 3.2.1, Lemma 3.4

Data-Aware Threshold Selection with Tolerance Parameter η

Instead of applying union bound over all |C| candidate thresholds (which splits failure probability δ/|C|), BARGAIN uses a tolerance parameter η that captures how often true precision oscillates around the target. The selection procedure (Eq. 11) chooses the smallest threshold where at most η larger thresholds are estimated to miss the target. Since precision is typically monotonically decreasing in real-world datasets, setting η=0 suffices, avoiding dependence on |C| in the failure probability bound. Section 3.2.2, Lemma 3.5

Adaptive Sampling (BARGAIN_P-A, BARGAIN_A-A)

Instead of uniform upfront sampling, BARGAIN iterates through candidate thresholds in decreasing order and, for each threshold, adaptively samples records from D^ρ until the estimation function confirms the threshold meets the target or the budget is exhausted. This avoids wasting samples on low proxy-score records that are uninformative for high-threshold estimation, and directs the sampling budget to where it is most needed. The anytime-valid property of the statistical test enables repeated testing during sampling without inflating error. Section 3.3, Algorithm 2

BARGAIN_A-A for Accuracy Target Queries

Adapts the framework for AT queries where the goal is to minimize oracle calls while meeting an accuracy target. Uses estimation function E_A^BARGAIN that tests whether proxy accuracy R_D(ρ) ≥ T by observing I[O(x)=P(x)] for sampled records. Includes an early stopping criterion based on whether T is within one standard deviation of the sample mean, avoiding excessive sampling at thresholds unlikely to meet the target. Section 4.1, Algorithm 3

BARGAIN_A-M (Multi-class per-class thresholds)

Extension of BARGAIN_A-A for multi-class classification that sets a separate cascade threshold per output class. Runs BARGAIN_A-A L times (for L classes), beneficial when the proxy is differently calibrated across classes. Section 4.1.3, Section B.4.2

BARGAIN_R-A for Recall Target Queries with Pre-filtering

For RT queries, uses a positive density concept d_r(ρ) to pre-filter records. Performs binary search on proxy scores to find a cutoff ρ_P where positive density exceeds a minimum threshold β, then runs BARGAIN_R-U on D^{ρ_P}. Addresses the challenge that uniform sampling yields few positives when the positive class is rare. Includes an impossibility result showing that no approach can guarantee high utility on all datasets when positives are scarce. Section 4.2.2, Algorithm 4

L Limitations
Author-stated For RT queries, when the number of true positives is small, no approach can achieve high utility while guaranteeing meeting the recall target (impossibility result). BARGAIN_R-A relaxes guarantees to the dense subset. Section 4.2.2, Section B.6.2
Inferred Guarantees hold relative to the oracle model's outputs, not ground truth. If the oracle itself is inaccurate, BARGAIN's guarantees are with respect to the oracle's (potentially wrong) answers. Section 2.1
Author-stated When proxy models are poorly calibrated (no correlation between proxy scores and correctness), the cascade framework provides low utility even though quality guarantees still hold. Section 2.2
Author-stated The method focuses on classification tasks (multiclass for AT, binary for PT/RT) and does not directly handle generation tasks like summarization or open-ended QA. Section 2.1
Inferred Adaptive sampling requires the ability to sample from D^ρ (records with proxy score > ρ), which requires proxy scores to be computed upfront for all records. Algorithm 2, Line 8
